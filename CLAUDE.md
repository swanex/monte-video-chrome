## Продукт
In-house инструмент студии MONTE VIDEO: генерация консистентных фонов (clean plates) для многокамерной (1–5 камер) съёмки на хромакее. Кеинг, цветокор и монтаж — отдельно в Adobe Premiere Pro. Полное ТЗ v2.1 лежит в Claude-проекте «Hrom MonteVideo» (`gemini-code-1795460833452.md`).

## Деплой

- Пуш в `main` = выкладка на прод. Перед пушем всегда `npm run build`.

## Термины в интерфейсе (утверждены владельцем)
Везде по-русски и одинаково: **Исходник** (кадр с зелёнкой), **Фон** (пустая локация, clean plate), **Превью** (фон + настоящий спикер, вырезанный из исходника), вкладка-шторка **Сравнение**.
Кнопки (глагол — это действие): «Сгенерировать фон для CAM N», «Сгенерировать фон для всех камер», «Скачать фоны (N)»; во вкладке «Локация» — «Сгенерировать панораму / заново», «Загрузить свою». Окно настроек — «Настройки» (не «Сетап», не «Установки»). Поле для заметок — «Комментарий режиссёра» (не оператора) — в промпте `Director notes`. Переключатель вида: «План + Превью», «План», «Превью». Меню проекта: «Дублировать проект» (без «(1 клик)»). Не смешивать с английским.

## Пайплайн генерации (с v0.3.0)
1. Модель генерирует **сразу пустой фон** (промпт `buildAutoPrompt(..., 'BG')`): исходник с зелёнкой — только как подсказка по ракурсу/свету, плюс референсы локации и Top-View план.
2. Приложение само кеит исходник (`src/chromakey.ts`) и кладёт настоящего спикера поверх фона → **превью**. Человек пиксель в пиксель, проверка честная: в Premiere идёт ровно тот фон, что проверен на превью.
3. Каждая генерация пишет в `history` пару: превью (stage 'A') + фон (stage 'B', `fromPreviewId`). Лента версий — одна строка «Версии».
- Почему так: в v0.2.0 модель перерисовывала человека (сдвиг/масштаб), а фон делался отдельной генерацией из превью — проверялась одна картинка, в монтаж шла другая.
- Мебель с плана в фоне не рисуется — она физически стоит на зелёнке и приходит при кеинге.

## Панорама локации (с v0.4.0) — `src/panorama.ts`, `src/PanoramaPanel.tsx`
- **Владелец: панорама — вспомогательная разметка, не результат.** Живёт узкой полосой во вкладке «Локация» под референсами (с v0.4.2). На главный экран не выносить: там важны план, превью и кнопки генерации без прокрутки.
- Одна широкая панорама комнаты на проект (`project.panorama`: versions, activeId, rotation, baseAz). Сгенерированная — 21:9, охват 150°; загруженная — любая шире 1.7:1, охват оценивается по пропорциям (`aspect*52`, 60–360°), правится ползунком.
- Модель цилиндрическая: x линейно по углу; центр панорамы = `baseAz` (средний Yaw камер в момент первой версии) + «Поворот комнаты». Вправо на панораме = рост угла на плане.
- Для камеры сектор: лучи Yaw ± FOV/2 из положения камеры пересекаются со «стенами» — окружностью `ROOM_RADIUS_M` (6 м) вокруг центра спикеров; азимуты точек пересечения → доли ширины панорамы. Поэтому рамка двигается и при повороте, и при сдвиге камеры. По высоте — пропорции кадра, смещение по Tilt. `cropCameraSector` вырезает кусок, он уходит в модель как IMAGE 2 (+ вся панорама как IMAGE 3). Без панорамы — старое поведение с фото-референсами.
- Фон помнит подпись панорамы (`bgPanoramaSig` = версия|поворот|охват). Не совпадает с текущей → метка «Фон устарел».
- Упрощения: комната — окружность, сектор не разворачивается из цилиндра в прямолинейную проекцию — модель исправляет при перерисовке.

## Ключевые факты предметной области
- Студия 12 × 9 м, сетка 1 м / 10 см.
- Зона хромакея — фиксированный полигон (5.7,0)→(12,0)→(12,5.1)→(9,5.1)→(5.7,1.25). Камеры в неё заходить не могут (Collision Guard).
- Камеры: Blackmagic Studio Camera 4K Pro (MFT, кроп ≈2.02), Pocket Cinema Camera 6K Pro (Super 35, кроп ≈1.56; в оконных режимах больше — считается по Crop Size). Объективы Olympus M.40-150mm F2.8, Sigma 18-35mm f/1.8 DC и др. Таблица сенсоров — `SENSORS` в `src/braw.ts`.
- Метаданные камер вставляются текстом из Premiere → Media File Properties (парсер `parseBrawMetadata` в `src/braw.ts`, проверен на реальном дампе BMPCC 6K Pro).
- Пайплайн: Этап А (локация вместо зелёнки со спикерами) → Этап Б (удаление людей, clean plate) → выгрузка `CAM_N_clean.png` в 1080p/2K/4K.
- API: прямой вызов Google AI Studio (Gemini) из браузера, ключ только в localStorage.
- Проекты и картинки — в IndexedDB (`src/storage.ts`): картинки отдельно по хэшу, проект хранит ссылки `idb:<ключ>`. Автосохранение с задержкой 300 мс, очистка неиспользуемых картинок при загрузке. Старые данные из localStorage переносятся автоматически.
- Акцентный цвет по умолчанию `#D3FD15`; заготовки: #D3FD15, #1473E6, #25D366, #CF362E, #F5F5F5 (выбраны владельцем). Как у Adobe: заливка = ровно выбранный цвет, текст на ней — `onAccent()` (белый, если контраст ≥4.5, иначе чёрный); акцентный текст на тёмном — `accentInk()` (осветление до контраста 4.5) — `src/accent.ts`. CSS-переменные `--accent` (ink) и `--accent-on`. Не писать `text-black`/`#0B0B0B` на акцентной заливке и `color: accentColor` для текста.
- Шрифт интерфейса — Inter 4 (переменный, с оптическими размерами), из npm `@fontsource-variable/inter`, лежит в сборке. Фичи `cv11`, `ss03`; `tnum` глобально не включать — расширяет дефис. Цифры/координаты — `font-mono`.
